Your APIs have some basic error handling (like raising HTTPException with 500 or 400 statuses), but they can definitely be strengthened.

Here is what is currently missing or could be improved to make these APIs production-ready and robust:

1. Handling Validation Errors (e.g., Phone Sanitization)
Currently, if sanitize_uganda_phone(payload.phone_number) throws an error (like a ValueError for a malformed phone number), FastAPI will likely crash with an unhandled 500 Internal Server Error. Fix: You should catch validation errors and return a 400 Bad Request so the client knows they sent bad data.

2. Database Exception Handling
Database operations (session.commit()) can fail for various reasons (e.g., connection drops, race conditions). If a commit fails, it will cause an unhandled 500 error. Fix: Wrap database commits in a try...except block, perform a session.rollback() on failure, and raise a clean 500 error.

3. Explicit Response Models & Status Codes
While FastAPI defaults to returning a 200 status code, explicitly defining the response_model and status_code in the @router.post decorator is a best practice. It automatically documents your API in Swagger UI and validates the output data. Fix: Add status_code=status.HTTP_200_OK to the decorators and define Pydantic models for the responses (e.g., OTPRequestResponse, OTPVerifyResponse).

4. Rate Limiting (Crucial for SMS APIs)
APIs that send SMS are prime targets for abuse (SMS bombing), which can cost you a lot of money. Right now, a malicious user could call /request-otp thousands of times a minute. Fix: Implement rate limiting (e.g., max 3 OTP requests per phone number every 5 minutes). You can also add a check to prevent requesting a new OTP if an active one was sent less than 60 seconds ago.

5. Token Generation on Login
In verify_otp, you successfully verify the user, but you just return their user_id. In a real-world scenario, you usually need to return a session token (like a JWT) so the user can authenticate subsequent requests to your protected endpoints.

```python
import os
import requests
from dotenv import load_dotenv

load_dotenv()

LABOREMUS_API_KEY = os.getenv("LABOREMUS_API_KEY")
LABOREMUS_BASE_URL = os.getenv("LABOREMUS_BASE_URL", "https://api.laboremus.ug") # Example staging/prod endpoint

def verify_nin_with_nira(nin: str):
    """
    Sends a NIN lookup request to Laboremus NIRA gateway
    """
    url = f"{LABOREMUS_BASE_URL}/v1/kyc/nira"
    headers = {
        "Authorization": f"Bearer {LABOREMUS_API_KEY}",
        "Content-Type": "application/json"
    }
    payload = {
        "nin": nin
    }

    response = requests.post(url, json=payload, headers=headers)
    
    if response.status_code == 200:
        data = response.json()
        return {
            "verified": True,
            "full_name": data.get("full_name"),
            "dob": data.get("dob"),
            "gender": data.get("gender"),
            "raw_data": data
        }
    else:
        return {
            "verified": False,
            "error": response.text
        }

```
